Issue body actions

On main commit 61d26a1d1e6f25d8d9fd7339e2a0ccf163358f26, a packet callback that raises leaves omi.ble.listen() and listen_payload() waiting. The caller cannot detect the failed audio consumer through the listener it is awaiting. Pending notification callbacks also outlive cancellation or disconnection of that listener.

The boundary is Bleak 0.22.3's real notification dispatcher: start_notify() schedules an async callback with asyncio.create_task(). Awaiting the user callback inside the SDK's async notification handler does not forward the resulting task failure to the separate listener coroutine. The listener keeps polling its disconnect event. I reproduced an unhandled background ValueError and a listener that timed out instead of raising that error.

This is distinct from #12948, whose awaitable recognition fix is already present. The existing exception tests await the captured notification handler directly; they do not exercise Bleak's dispatch or await the listener for the callback error. It is a focused instance of the broader lifecycle work discussed in #13011.

Reproduction and candidate: I have a local patch and hermetic tests using the installed, unmodified Bleak 0.22.3 BleakClient with an in-memory backend replacing device I/O. The backend emits notifications synchronously so the real Bleak implementation schedules the callback tasks. No Bluetooth hardware, recordings, credentials, or live provider is used.

  • Original SDK suite: 53 passing tests on Python 3.12.
  • Unchanged production source plus the new regressions: 13 failures. Ten cover synchronous callbacks, coroutines, Futures, Tasks and custom awaitables through both listener functions; three cover in-flight task cleanup on callback error, cancellation and disconnect.
  • Candidate full suite: 64 passing tests on Python 3.12 and on Python 3.11.17. The repository's bash sdks/python/test.sh also passes, using pytest 8.4.1, Bleak 0.22.3 and websockets 14.0.
  • The two previous handler-only exception tests are replaced by the ten listener-level cases; the existing success, awaitable, service-selection and disconnect coverage remains.

The candidate forwards the first callback exception to the awaiting listener, cancels and awaits in-flight notification callbacks on exit, ignores late notifications, and preserves existing payload stripping and service selection. It retains the existing one-second polling interval. This scope covers the high-level Python listen() and listen_payload() helpers; it does not claim a cross-language lifecycle fix or physical-device validation.

Local repository preflight now exits successfully: 14 selected checks in 55.66s, after hydrating the required tracked inputs. The history-based failure-class ratchet explicitly skips because this clone is shallow, and the check-runner self-tests report one skipped test. These are local working-tree results, not upstream CI or validation of a committed PR. The candidate patch and regressions are included below for review.

+"""Exercise Bleak's real notification dispatch with an in-memory BLE backend."""
+
+from __future__ import annotations
+
+import asyncio
+from functools import partial
+from types import SimpleNamespace
+from unittest.mock import patch
+
+import pytest
+from bleak import BleakClient
+
+from omi.ble import listen, listen_payload
+from omi.constants import PACKET_HEADER_BYTES
+
+
+class NotificationBackend:
+    """Replace only device I/O; Bleak still schedules notification callbacks."""
+
+    def __init__(self, address, *, disconnected_callback, ready, **_kwargs):
+        self.address = address
+        self.disconnected_callback = disconnected_callback
+        self.ready = ready
+        self.is_connected = False
+        self.disconnect_count = 0
+        self.notification = None
+        self.services = SimpleNamespace(
+            get_characteristic=lambda _uuid: SimpleNamespace(handle=1)
+        )
+
+    async def connect(self, **_kwargs):
+        self.is_connected = True
+        return True
+
+    async def disconnect(self):
+        self.disconnect_count += 1
+        self.is_connected = False
+        return True
+
+    async def start_notify(self, _characteristic, callback, **_kwargs):
+        self.notification = callback
+        self.ready.set_result(self)
+
+    def emit(self, payload=b"audio"):
+        self.notification(bytearray(b"\x00" * PACKET_HEADER_BYTES + payload))
+
+
+class FailingAwaitable:
+    def __init__(self, error):
+        self.error = error
+
+    def __await__(self):
+        async def fail():
+            raise self.error
+
+        return fail().__await__()
+
+
+@pytest.mark.parametrize("listen_fn", [listen, listen_payload])
+@pytest.mark.parametrize(
+    "callback_kind", ["sync", "coroutine", "future", "task", "custom"]
+)
+def test_notification_error_reaches_listener(listen_fn, callback_kind):
+    async def run():
+        loop = asyncio.get_running_loop()
+        ready = loop.create_future()
+        unhandled = []
+        loop.set_exception_handler(lambda _loop, context: unhandled.append(context))
+        failure = ValueError("audio consumer failed")
+
+        async def fail():
+            await asyncio.sleep(0)
+            raise failure
+
+        def on_packet(packet):
+            expected = (
+                b"audio"
+                if listen_fn is listen_payload
+                else b"\x00" * PACKET_HEADER_BYTES + b"audio"
+            )
+            assert packet == expected
+            if callback_kind == "sync":
+                raise failure
+            if callback_kind == "coroutine":
+                return fail()
+            if callback_kind == "future":
+                future = loop.create_future()
+                loop.call_soon(future.set_exception, failure)
+                return future
+            if callback_kind == "task":
+                return asyncio.create_task(fail())
+            return FailingAwaitable(failure)
+
+        client_factory = partial(BleakClient, backend=NotificationBackend, ready=ready)
+        with patch("omi.ble.BleakClient", client_factory):
+            listener = asyncio.create_task(listen_fn("test-device", on_packet))
+            try:
+                backend = await asyncio.wait_for(ready, timeout=2)
+                # Backend notifications are synchronous. Real Bleak creates the
+                # async callback task, so this never awaits the SDK's handler.
+                backend.emit()
+                with pytest.raises(ValueError) as raised:
+                    await asyncio.wait_for(listener, timeout=2)
+                assert raised.value is failure
+                assert backend.disconnect_count == 1
+                assert not backend.is_connected
+                await asyncio.sleep(0)
+                assert unhandled == []
+            finally:
+                listener.cancel()
+                await asyncio.gather(listener, return_exceptions=True)
+
+    asyncio.run(run())
+

+@pytest.mark.parametrize("ending", ["callback_error", "cancel", "disconnect"])

+

+
+        client_factory = partial(BleakClient, backend=NotificationBackend, ready=ready)
