Summary

Severity: Medium ($150 USDC — Stage 1 Bug Bounty)
Affected Stage-1 Components:

  1. src/privacy/pool.rs (ShieldedPool::credit_commitment, lines 120–165), src/privacy/merkle.rs (MerkleTree::insert), and src/storage/privacy.rs (PrivacyStorage)
  2. src/storage/privacy.rs (PrivacyStorage::get_all_commitments lines 184–217, get_all_asset_supplies lines 434–452, insert_commitments_batch lines 146–165)
  3. programs/paraloom/src/lib.rs (slash_validator lines 1084–1153, deposit_note lines 203–250, register_validator lines 805–814)

Finding 1: Non-Atomic Cross-CF Deposit Persistence in ShieldedPool::credit_commitment Permanently Loses Shielded Supply on Crash/Error

Root Cause

In ShieldedPool::credit_commitment (src/privacy/pool.rs:144–162), crediting a deposit executes two separate, non-atomic RocksDB writes across two different column families (CF_MERKLE_TREE and CF_POOL_STATE):

let _index = self.commitment_tree.insert(&commitment).await?; // 1st RocksDB write to CF_MERKLE_TREE
self.deposited.write().await.insert(commitment.clone());
...
let mut supplies = self.supplies.write().await;
let supply = supplies.entry(asset_id).or_insert(0);
*supply += amount;

if let Some(storage) = &self.storage {
    storage.set_asset_supply(&asset_id, *supply)?; // 2nd RocksDB write to CF_POOL_STATE
}

Impact

If storage.set_asset_supply fails or the node process crashes/terminates between the CF_MERKLE_TREE write (insert_commitment) and the CF_POOL_STATE write (set_asset_supply):

  1. On restart, ShieldedPool::with_storage (src/privacy/pool.rs:64–78) seeds the idempotency set self.deposited from storage.get_all_commitments()? (which already contains commitment from CF_MERKLE_TREE), while self.supplies is loaded from storage.get_all_asset_supplies()? (which is missing amount).
  2. When the bridge EventListener replays the unacknowledged deposit on restart, credit_commitment hits if self.deposited.read().await.contains(&commitment) { return Ok(commitment); } (line 137) and returns Ok(commitment) as a no-op, permanently leaving supplies[asset_id] (and total_supply) understated relative to the committed notes in the Merkle tree.

Finding 2: PrivacyStorage::get_all_commitments Drops Leaf Indices Without Contiguity Validation and get_all_asset_supplies Silently Skips Corrupted Supply Entries

Root Cause

  1. In PrivacyStorage::get_all_commitments (src/storage/privacy.rs:184–217), leaf records (index, commitment) are read from CF_MERKLE_TREE, sorted by index, and projected into a Vec<Commitment> via indexed.into_iter().map(|(_, c)| c).collect() without verifying that index == pos as u64 (contiguous 0..N indexing).
  2. In PrivacyStorage::get_all_asset_supplies (src/storage/privacy.rs:440–442), corrupted or malformed records under SUPPLY_PREFIX (id_bytes.len() != 32 || value.len() != 8) are silently ignored via continue instead of returning an Err, unlike get_total_supply (line 356) and get_asset_supply (line 403).
  3. In PrivacyStorage::insert_commitments_batch (src/storage/privacy.rs:158), start_index + i as u64 is computed without checked_add.

Impact

  • Any missing leaf index or non-zero starting index in CF_MERKLE_TREE silently shifts all subsequent leaves to lower positions on MerkleTree::with_storage reload, producing a divergent Merkle root and invalidating every subsequent note's leaf_index.
  • A corrupted per-asset supply entry in CF_POOL_STATE is silently dropped by get_all_asset_supplies(), resetting that asset's reloaded supply to 0 without surfacing a storage error.

Finding 3: Sub-Rent slashed_funds_vault & bridge_vault Balances Cause Runtime InsufficientFundsForRent Aborts in slash_validator and deposit_note

Root Cause

  1. slash_validator (programs/paraloom/src/lib.rs:1084–1153):
    slashed_funds_vault (seeds = [b"slashed_funds_vault"], lib.rs:2612) is an uninitialized 0-byte system PDA that starts at 0 lamports (0-byte rent-exempt minimum is Rent::get()?.minimum_balance(0) = 890,880 lamports). slash_validator computes slash_amount = (old_stake as u128 * slash_percentage as u128 / 100) as u64 and directly transfers slash_amount lamports into slashed_funds_vault: 
    **validator_account.to_account_info().try_borrow_mut_lamports()? -= slash_amount;
**ctx.accounts.slashed_funds_vault.to_account_info().try_borrow_mut_lamports()? += slash_amount;
    Whenever slashed_funds_vault.lamports() + slash_amount falls in 1..890,880 (for example, an unbonding validator whose remaining SOL unbonding_amount after an earlier 95% slash is 50,000,000 lamports / 0.05 SOL is slashed by 1% -> slash_amount = 500,000 < 890,880, while still holding 99,000,000,000 PARALOOM tokens in token_unbonding_amount), the Solana runtime aborts the entire transaction at instruction exit with TransactionError::InsufficientFundsForRent on slashed_funds_vault — reverting both the SOL slash and the token_slash SPL collateral burn.
  2. deposit_note (programs/paraloom/src/lib.rs:203–250):
    initialize does not seed bridge_vault (seeds = [b"bridge_vault"]), so bridge_vault starts at 0 lamports. deposit_note only checks amount > 0 and projected_vault_balance <= deposit_cap. A first deposit with 0 < amount < Rent::get()?.minimum_balance(0) (890,880 lamports) passes program validation but aborts in the Solana runtime with TransactionError::InsufficientFundsForRent on bridge_vault.
  3. register_validator (programs/paraloom/src/lib.rs:810–813):
    register_validator checks stake_amount >= MIN_VALIDATOR_STAKE rather than checking against ctx.accounts.validator_registry.minimum_stake (which slash_validator uses as the deactivation bar at lib.rs:1103).

Fix

  1. Atomic commitment + supply write batch (src/storage/privacy.rs, src/privacy/merkle.rs, src/privacy/pool.rs):
    • Add PrivacyStorage::insert_commitment_with_supply using a single fsync'd rocksdb::WriteBatch across CF_MERKLE_TREE and CF_POOL_STATE, and wire MerkleTree::insert_with_supply into ShieldedPool::credit_commitment with checked supply addition prior to persistence.
  2. Storage integrity checks (src/storage/privacy.rs):
    • Validate contiguous 0..N leaf indices in get_all_commitments(), return Err on corrupted key/value sizes in get_all_asset_supplies(), and use checked_add in insert_commitments_batch().
  3. On-chain vault rent-floor & stake floor guards (programs/paraloom/src/lib.rs):
    • In deposit_note, require projected_vault_balance >= Rent::get()?.minimum_balance(0) before invoking the transfer CPI.
    • In slash_validator, ensure slashed_funds_vault never ends in 1..rent_floor (promoting slash_amount to cover the rent floor when old_stake >= needed, or 0 if old_stake < needed so the token collateral burn and slash state update still succeed).
    • In register_validator, enforce stake_amount >= ctx.accounts.validator_registry.minimum_stake.max(MIN_VALIDATOR_STAKE).
