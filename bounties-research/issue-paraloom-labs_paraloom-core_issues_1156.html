[BOUNTY] Medium: peer_id_from_multiaddr extracts the first /p2p/<peer_id> instead of the trailing target PeerId on p2p-circuit multiaddrs, permanently suppressing co-validator keep-alive redials and poisoning Kademlia routing

Summary

  • Severity: Medium (up to $150 USDC — Stage 1 Bug Bounty: P2P / Kademlia / circuit-relay & co-validator keep-alive path in src/network/protocol.rs)
  • Affected Component: src/network/protocol.rs (peer_id_from_multiaddr lines 47–55, connect_to_bootstrap lines 439–470, redial_disconnected_co_validators lines 484–516, listen_via_relay lines 553–597)
  • Commit Audited: 9e8c8e6 (main)

Two related defects in src/network/protocol.rs break circuit-relay v2 (#226) multiaddr handling across co-validator keep-alive redials, Kademlia DHT registration, and relay slot reservation:

  1. peer_id_from_multiaddr (src/network/protocol.rs:47–55) Extracts the First /p2p/<peer_id> Component Instead of the Trailing Target PeerId:

    • The doc comment on peer_id_from_multiaddr states: "Extract the trailing /p2p/<peer_id> component from a multiaddr if present."
    • However, the implementation calls addr.iter().find_map(...) from the front of the multiaddr, returning the first Protocol::P2p(peer_id) encountered rather than inspecting the trailing component (addr.iter().last()).
    • For any NATed validator or bootstrap peer reachable via a libp2p circuit-relay v2 server (#226), its dialable multiaddr has the standard form:
      /<relay-transport>/p2p/<relay_peer_id>/p2p-circuit/p2p/<target_peer_id>
    • On such an address, peer_id_from_multiaddr returns Some(relay_peer_id) instead of Some(target_peer_id) — and on a bare circuit address /<relay-transport>/p2p/<relay_peer_id>/p2p-circuit (with no target /p2p/<peer_id> suffix at all), it falsely returns Some(relay_peer_id) instead of None.
    • Impact 1 — Co-Validator Keep-Alive Permanently Suppressed (redial_disconnected_co_validators, src/network/protocol.rs:484–516):
      • redial_disconnected_co_validators extracts pid = peer_id_from_multiaddr(&addr) and skips redialing whenever connected.contains(&pid.to_bytes()) (line 506).
      • When a NATed co-validator (coval_peer) is configured via a relayed multiaddr /.../p2p/<relay_peer>/p2p-circuit/p2p/<coval_peer> and its circuit connection drops while the node remains connected to the public relay anchor (relay_peer), peer_id_from_multiaddr(&addr) returns Some(relay_peer). Because connected.contains(&relay_peer.to_bytes()) is true, redial_disconnected_co_validators hits continue; // already connected — nothing to do (line 507) on every keep-alive tick and never redials the disconnected co-validator, causing a permanent 2-of-2 / quorum settlement co-signing outage.
    • Impact 2 — Kademlia Routing Table Poisoning (connect_to_bootstrap line 453 and redial_disconnected_co_validators line 509):
      • Both connect_to_bootstrap and redial_disconnected_co_validators call swarm.behaviour_mut().kad.add_address(&pid, addr.clone()).
      • When addr is /.../p2p/<relay_peer>/p2p-circuit/p2p/<target_peer>, kad.add_address registers target_peer's circuit multiaddr as an address of relay_peer while leaving target_peer completely absent from Kademlia's routing table. Subsequent Kademlia queries or dials targeting relay_peer attempt to dial target_peer through the relay circuit and fail with WrongPeerId.

  2. listen_via_relay (src/network/protocol.rs:553–597) Double-Appends /p2p-circuit and Registers Circuit Multiaddrs in Kademlia When relay_addr Includes /p2p-circuit:

    • If an operator configures relay_address with the trailing /p2p-circuit suffix (e.g., /ip4/1.2.3.4/tcp/9000/p2p/<relay_peer>/p2p-circuit) or mistakenly supplies a relayed target address (/.../p2p/<relay_peer>/p2p-circuit/p2p/<target_peer>), listen_via_relay registers the unstripped /p2p-circuit multiaddr as the relay server's own Kademlia transport address (line 580) and unconditionally appends a second .with(Protocol::P2pCircuit) (line 587), producing an invalid /p2p-circuit/p2p-circuit listener multiaddr.

Vulnerability Details

1. peer_id_from_multiaddr (src/network/protocol.rs:42–55)

/// Extract the trailing `/p2p/<peer_id>` component from a
/// multiaddr if present. Used by bootstrap registration to learn
/// the PeerId without dialling first; if the operator gives us a
/// bare network multiaddr (no /p2p/ suffix) we fall back to dial
/// only.
fn peer_id_from_multiaddr(addr: &Multiaddr) -> Option<PeerId> {
    addr.iter().find_map(|proto| {
        if let libp2p::multiaddr::Protocol::P2p(peer_id) = proto {
            Some(peer_id)
        } else {
            None
        }
    })
}

And in redial_disconnected_co_validators (src/network/protocol.rs:505–514):

            if let Some(pid) = peer_id_from_multiaddr(&addr) {
                if connected.contains(&pid.to_bytes()) {
                    continue; // already connected — nothing to do
                }
                swarm.behaviour_mut().kad.add_address(&pid, addr.clone());
            }
            match swarm.dial(addr.clone()) {
                Ok(()) => log::info!("co-validator keep-alive: re-dialing {}", addr),
                Err(e) => log::debug!("co-validator redial to {} failed (will retry): {}", addr, e),
            }

Because addr.iter().find_map(...) yields the first Protocol::P2p component in the multiaddr:

  • On /ip4/203.0.113.10/tcp/9000/p2p/<relay_peer_id>/p2p-circuit/p2p/<coval_peer_id>, pid is relay_peer_id instead of coval_peer_id.
  • As long as the validator maintains its connection to the public relay anchor relay_peer_id (which is the normal steady state whenever a validator uses that relay anchor for bootstrap/NAT traversal), connected.contains(&relay_peer_id.to_bytes()) is true, so redial_disconnected_co_validators permanently skips coval_peer_id after any transient circuit drop or relay reservation renewal.
  • Even when relay_peer_id is not yet in connected, swarm.behaviour_mut().kad.add_address(&pid, addr.clone()) (both here and in connect_to_bootstrap at line 453) associates coval_peer_id's /p2p-circuit/p2p/<coval_peer_id> address with relay_peer_id in Kademlia.

2. listen_via_relay (src/network/protocol.rs:553–597)

    pub async fn listen_via_relay(&self, relay_addr: &str) -> Result<()> {
        let relay_addr: Multiaddr = relay_addr
            .parse()
            .with_context(|| format!("parsing relay address {}", relay_addr))?;

        let relay_peer = peer_id_from_multiaddr(&relay_addr).ok_or_else(|| {
            anyhow!(
                "relay address {} has no /p2p/<peer_id> suffix; cannot reserve a circuit",
                relay_addr
            )
        })?;
...
        swarm
            .behaviour_mut()
            .kad
            .add_address(&relay_peer, relay_addr.clone());

        let circuit_addr = relay_addr
            .clone()
            .with(libp2p::multiaddr::Protocol::P2pCircuit);
        swarm
            .listen_on(circuit_addr.clone())
            .with_context(|| format!("listening on relay circuit {}", circuit_addr))?;

If relay_addr is configured with a trailing /p2p-circuit (or as a chained relayed address /.../p2p/<relay>/p2p-circuit/p2p/<target>), listen_via_relay does not strip a trailing Protocol::P2pCircuit or reject intermediate Protocol::P2pCircuit components before registering relay_addr in Kademlia and appending .with(Protocol::P2pCircuit).

Fix

  1. Match the Trailing Component in peer_id_from_multiaddr (src/network/protocol.rs:47–51):
    • Inspect addr.iter().last() and return Some(peer_id) if and only if the final component is libp2p::multiaddr::Protocol::P2p(peer_id).
    • Relayed target multiaddrs /.../p2p/<relay>/p2p-circuit/p2p/<target> now return Some(target), and bare /.../p2p/<relay>/p2p-circuit addresses without a target peer suffix return None.
  2. Normalize Trailing /p2p-circuit and Reject Chained Circuit Multiaddrs in listen_via_relay (src/network/protocol.rs:550–578):
    • Pop a single trailing Protocol::P2pCircuit component if present so operators can provide either /.../p2p/<relay_id> or /.../p2p/<relay_id>/p2p-circuit, while still registering the clean direct transport multiaddr /.../p2p/<relay_id> in Kademlia and listening on a single /p2p-circuit suffix.
    • Return an error if relay_addr still contains any intermediate Protocol::P2pCircuit component (e.g., /.../p2p/<relay>/p2p-circuit/p2p/<target>).

Reproduction & Verification

Run the unit tests in src/network/protocol.rs:

cargo test --lib network::protocol::tests

Specifically:

  • network::protocol::tests::peer_id_extracted_from_relayed_multiaddr_returns_target_not_relay
  • network::protocol::tests::redial_disconnected_co_validators_does_not_skip_relayed_peer_when_relay_is_connected
  • network::protocol::tests::listen_via_relay_normalizes_trailing_p2p_circuit_and_rejects_chained_circuit
