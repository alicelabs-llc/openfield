The problem

Currently a feature that is not working ideally is saved searches over 25. See the existing issue describing the problem

Deleting_TopFewSavedSearch_DisplaysBottomFewSavedSearches.mp4

This is a pagination issue or rather a lack of, since the saved searches table component is based on the search results table which limits the results to 25, but we have not added the ability to support pagination.

If you have access to the Simpler Grants slack, here is a slack thread on the issue and the fix.

Steps to reproduce

Sadly, to get this problem to be replicated, is a 25 step process 😓

  • Launch the URL.
  • Log in.
  • Enter a search term and/or apply search criteria.
  • In the Current search query section, click Save.
  • In the Name this search query modal, enter a name and click Save.
  • Repeat steps 3-5 until more than 25 saved searches have been created.
  • Navigate to Workspace -> Saved Search Queries.
  • Observe the list of saved searches.
  • Delete the top two saved searches.
  • Observe the list again.
  • Actual result
    • When more than 25 saved searches exist, only 25 are displayed on the Workspace -> Saved Search Queries page. There is no indication that additional saved searches exist.
    • After deleting the top two displayed saved searches, the previously hidden saved searches become visible, and the page still displays 25 saved searches.
  • Expected result
    • All saved searches should be discoverable and accessible to the user, with a page number appearing once the user has more than 25 searches.

Requirements

  1. Users can view more than 25 searches
  2. When user has < 26 saved searches, they see no pagination on the saved search queries /saved-search-queries/ page
  3. When user has > 25 searches, a pagination element appears at the top and bottom of their saved searches. (see attached images)

Because a 25 item page is quite long, these images are of the top and bottom of the results table.

  1. Page numbers should appear only when there are more than 25 results, and should include the current page number, a representation of the number of pages, and 'previous' and 'next' page buttons.
  2. Test coverage for this feature, including saving more than 25 queries and looking for a pagination element to appear. (depending on test implementation it may be difficult to make more than 2 pages show up)

Implementation details

Pagination should be reused from another page doing pagination already (for example the search page or applications list) and connecting some dots for the API call.

Out of scope

Some observed whitespace and overflow issues with the current layout that are out of scope for this issue and will appear in a separate issue once pagination is implemented. See some example images

For now the requirement is that 'no new whitespace and content fitting issues are introduced by this feature'
