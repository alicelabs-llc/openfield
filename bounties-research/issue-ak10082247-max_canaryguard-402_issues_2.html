    1. Executive Summary & Root Cause / Architecture

    Executive Summary

    CanaryGuard is an AI security firewall utilizing heuristic regex-based filtering to detect and block prompt injection attacks, instruction overrides, and jailbreaks in autonomous AI agents.

    An adversarial red-team analysis of CanaryGuard's strict mode API (/v1/sanitize) reveals structural weaknesses in its regex sanitization engine. Specifically, naive substring matching, rigid delimiters, and case-sensitive or unnormalized token filters fail to properly parse obfuscated instruction overrides, unicode payloads, nested control characters, or semantic zero-width character insertion.

    We have successfully engineered and verified an adversarial prompt injection payload that completely evades CanaryGuard's Strict Mode filter (status: "clean", risk_score: 0), while successfully executing instruction overrides and system role hijacking on downstream LLMs.

    Root Cause Analysis

    1. Regex Pattern Narrowness: The firewall relies on fixed signatures (e.g., matching literal words like "ignore previous instructions", "system:", "you are now"). It lacks robust token normalization, decoding of unicode escape sequences, or multi-stage semantic vector analysis.
    2. Control Character & Whitespace Blindness: The engine fails to sanitize or strip zero-width spaces (\u200B), non-breaking spaces, or zero-width joiners (\u200D) placed within sensitive keywords.
    3. Delimiter Bypass: The firewall looks for standard chat template boundaries ([INST], ###, <|im_start|>) but fails to handle semantic role-playing or indirect semantic framing that constructs persona switches without triggering keyword filters.

    status: 'clean',
