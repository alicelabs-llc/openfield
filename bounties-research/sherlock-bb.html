faq

What is Sherlock’s bug bounty offering?
Sherlock’s bug bounty offering helps teams receive and triage vulnerability reports on live Web3 code after launch. It keeps white hats incentivized to keep testing production systems
Why should a team have a bug bounty after launch?
Launch is not the endof risk. A bug bounty helps teams keep security attention on live code as value, usage, and attack surface grow.
How is Sherlock’s bug bounty different from a standalone bounty setup?
Sherlock’s bug bounty offering is connected to earlier security work. That means bounty design can benefit from existing audit context and known risk areas in the codebase.
When should a team launch its bug bounty?
Ideally around launch, not months later. Early post-launch periods can carry serious risk, so white hats should already be incentivized when the code goes live.
What happens if a valid vulnerability is found through the bug bounty?
A valid issue can be triaged through the bug bounty flow, and qualifying codebases may also have access to Sherlock Shield. Coverage is subject to the claims process and program terms.
How does Sherlock’s bug bounty fit into lifecycle security?
Bug bounties are Sherlock’s post-launch active protection layer. They carry security work beyond development and audit so teams are not left exposed after launch.
