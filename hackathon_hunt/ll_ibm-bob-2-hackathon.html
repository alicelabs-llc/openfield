About the Technology

Back for Another Hack — Meet IBM Bob 2.0

After the success of our IBM Bob hackathon in May, we're hosting a challenge around Bob 2.0 — an upgraded AI-powered development partner designed to help developers work with real systems, not just code snippets.

Bob 2.0 operates with full repository context, allowing developers to understand how software is structured, reason through logic, and navigate complex codebases more effectively than ever before.

It supports practical development tasks and helps builders at any skill level move from idea to implementation with greater clarity and confidence.

This second hackathon is your chance to put the latest version of Bob to work on a real project and see how it fits into your workflow.

IBM Bob 2.0 - Challenge & Getting Started
The Challenge

Build with purpose using IBM Bob 2.0

The challenge statement:

Create a solution that improves a specific developer workflow, such as onboarding, debugging, code review, testing, application maintenance, or release and deployment processes.

Start by clearly defining a problem where time, effort, or errors are too high today. Then, using IBM Bob 2.0, build a working prototype on a real or sample project that demonstrates a full solution to improve the specified workflow.

Leverage features like Agent mode, parallel tasks, subagents, and document understanding to manage and improve multiple steps, not just assist with coding. Clearly demonstrate impact by showing how your solution increases productivity, reduces manual effort, errors, and rework, or significantly shortens the time required to complete tasks.

What to submit?

Submit your project through the lablab.ai platform before the deadline. Make sure all fields and required deliverables below are completed.

📋 Basic Information

  • Project Title
  • Short Description
  • Long Description
  • IBM Bob Usage Statement
  • Technology & Category Tags

💻 Application & Code

  • Public Code Repository
  • IBM Bob Task Session Summary Screenshots
  • Demo Application Platform
  • Application URL

📸 Media & Presentation

  • Cover Image
  • Video Demonstration
  • Slide Presentation

Important Requirements

• Written statements: Complete both the Problem & Solution Statement and IBM Bob Usage Statement. Each must be 500 words or less.

• IBM Bob evidence: Your repository must include the code/files where IBM Bob assisted, plus IBM Bob task session summary screenshots from each team member.

• Repository access: Make sure your code repository is publicly accessible.

• Video: Your video demonstration must be 3 minutes or less, with at least 90 seconds showing your solution in action.

Deliverable Details

🎥 Video Demonstration of the Team's Solution

Upload an MP4 video demonstration of your solution through the submission form. Three minutes is the maximum length. Judges will not watch more than 3 minutes of your video.

Briefly introduce the specific issue you are looking to improve or address, but leave at least 90 seconds to show your solution in action, on screen, and demonstrate how it works.

Clearly demonstrate how you utilized IBM Bob in your solution. Include narration to describe what you are demonstrating.

Creativity is encouraged! The judges will see lots of screen-sharing videos, so think about how your video will stand out and catch the judges' attention with a compelling, high-quality presentation.

📝 Long Description — Problem & Solution Statement (500 words or less)

Use the Long Description field to describe your project in 500 words or less.

Include the specific problem or challenge that your solution is designed to address.

Describe what your solution is, including its target users, how they would interact with the solution, and why the solution is creative and unique.

Provide clear details on how your project effectively and efficiently addresses the stated issue in a new way the judges have never seen before.

🤖 IBM Bob Usage Statement (500 words or less)

In 500 words or less, provide clear and specific details on how and where your team used IBM Bob to build your project. Be specific about how IBM Bob contributed throughout the development of your solution.

If applicable, also describe how your project uses IBM watsonx.ai or IBM watsonx Orchestrate.

💻 Code Repository & IBM Bob Task Session Summary Screenshots

Any code or files you created for the project, including those where IBM Bob assisted in the development, should be uploaded and organized in a GitHub repository (or another source control system such as GitLab or Bitbucket) for your project.

  • Share a publicly accessible link to your repository.
  • Your repository must also include each team member's screenshots of IBM Bob task session summaries for your project. The hackathon guide, which will be available when the hackathon begins, will include step-by-step instructions on how to capture these.
  • Participants may use the GitHub IBM Hackathon repository template for their project. Refer to the quickstart instructions to learn how to use the template.
  • The template includes ".gitignore" and ".bobignore" files to help prevent the accidental exposure of credentials and other sensitive information.

Important: If IBM Cloud credentials (API keys, passwords, or other sensitive secrets) are detected in your repository through IBM security monitoring, your IBM Cloud account may be suspended immediately. To avoid account suspension during the hackathon, do not expose any IBM Cloud credentials in your repository, especially within code files. Use the provided repository template, as it includes safeguards designed to help prevent accidental credential exposure.

Judging Criteria

Projects are evaluated by our judges using the criteria below.

Application of Technology

How complete and well thought-out the project is, with a clear application of IBM Bob 2.0.

Presentation

The clarity and effectiveness of the project presentation.

Business Value

The impact and practical value, considering how effectively the solution addresses a high priority issue.

Originality

The uniqueness and creativity of the solution and the approach in applying IBM Bob 2.0 to address the stated issue.
