Context

SpaceApp publishes three images from one Dockerfile: spaceapp-core (API, web server, Temporal worker), spaceapp-cli (the CLI host that runs the AI coding CLIs in PTYs) and spaceapp-browser (Browser Host plus Chromium). All three build FROM runtime-base. That stage copies the whole monorepo output into every image: all of node_modules after npm prune --omit=dev, all of apps/, all of packages/ and agent-skills/. So:

  • the CLI image ships the API, the web app, the Temporal SDK with its native core bridge, pdfjs and @napi-rs/canvas, though it only runs packages/cli-host/dist/main.js;
  • the browser image ships the CLI host, node-pty, the web app and the Temporal SDK, though it only runs apps/api/dist/browser-host-main.js;
  • the core image ships the CLI host and node-pty, plus native prebuilds for platforms it never runs on.

Sizes in the latest Container matrix run on main (scripts/container-image-size-budget.mjs):

Image linux/amd64 linux/arm64 Budget
core 1044.7 MiB 1066.9 MiB 1100 MiB
browser 1719.9 MiB 1735.0 MiB 1750 MiB
cli 1386.0 MiB 1237.1 MiB 2800 MiB

The browser image is 15 MiB from its budget. The core budget already had to be raised for 1.1.5, and KNOWN_LIMITATIONS.md (EXT-C-F20) names the core image size as the reason some functionality cannot be added to core. Every user downloads these images on install and on every update.

Goal

Each image contains only what its service runs, on both architectures, with no change in behavior.

Acceptance criteria

  • Each target gets its own production dependency closure, for example a per-target build stage that installs only the workspaces that target runs, or a pruned deploy directory per entrypoint. Shared layers stay shared where it helps the total download.

  • Measured with scripts/container-image-size-budget.mjs on both linux/amd64 and linux/arm64:

    • core at most 850 MiB,
    • browser at most 1350 MiB,
    • cli at most 1000 MiB.

    The budgets in the script and its test (scripts/tests/container-image-size-budget.test.mjs) are lowered to the new sizes plus a small margin, with the measurements recorded in the comment as today.

  • No functional change. Each image keeps its entrypoint, the non-root spaceapp user (uid/gid 10001), the healthcheck, /app/deploy/docker/* scripts, the *-vscode-parity wrapper links, OpenCode in the CLI image, LICENSE/NOTICE/THIRD_PARTY_NOTICES.md, the owner and backup scripts in core, and the security patches applied to npm in runtime-base.

  • Smoke checks in .github/workflows/containers.yml for every target and architecture, so a missing module fails CI instead of an install:

    • core starts against a pgvector PostgreSQL service, runs migrations and answers /readyz with ok: true;
    • cli starts the CLI host and accepts a connection on its socket;
    • browser starts the Browser Host and launches headless Chromium once.

  • Full-stack check with the launcher on Linux: build the three images locally, tag them as the version the launcher expects, run install --profile large, and confirm that an OpenCode pane starts and a browser pane opens a page. Put the steps and output in the PR.

  • The security workflow's image scans (.github/workflows/security.yml) and the release workflow (.github/workflows/release.yml) still pass. scripts/tests/public-docker-distribution.test.mjs and scripts/tests/public-compose-config.test.mjs are updated where they assert the Dockerfile layout.

  • The README's disk requirements are updated if the smaller images change them.

How to test

for target in core browser cli; do
  docker buildx build --platform linux/amd64 --target "$target" -t "spaceapp-local:$target-amd64" --load .
  node scripts/container-image-size-budget.mjs --target "$target" --image "spaceapp-local:$target-amd64"
done
# repeat with --platform linux/arm64 (QEMU), as .github/workflows/containers.yml does
node --test scripts/tests/*.test.mjs

Then run the smoke checks above and a launcher install against the local images.

Out of scope

  • Changing the base image (Debian trixie slim with Node 22), the Node version or the Chromium source.
  • Moving features between services, for example moving OpenCode into core (EXT-C-F20 describes that trade-off).
  • Removing tools the services use at runtime (git, ripgrep, postgresql-client, sqlite3, gosu, ...) unless the PR shows the target never calls them.

Pointers

  • Dockerfile (stages build, runtime-base, core, browser, cli)
  • deploy/docker/core-entrypoint.sh, deploy/docker/core-supervisor.mjs (core runs apps/api/dist/server.js, apps/worker/dist/worker.js, apps/web/server.mjs and packages/db/dist/migrate.js), deploy/docker/cli-entrypoint.sh, deploy/docker/browser-entrypoint.sh
  • scripts/container-image-size-budget.mjs, .github/workflows/containers.yml
  • packages/run-spaceapp/templates/compose.yml (how the images are run)
  • Before opening a PR, run the checks in CONTRIBUTING.md.
