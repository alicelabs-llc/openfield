Summary

  • Proposed Tier: Medium ($150 USDC — docs/bug-bounty.md Stage 1 On-Chain Bridge & Dual-Stake Validator Invariant)
  • Target Repository: paraloom-labs/paraloom-core
  • Affected Files (In-Scope programs/paraloom/):
    • programs/paraloom/src/lib.rs (deactivate_validator at lines 1634–1656, withdraw_unbonded_stake at lines 1673–1746, slash_validator at lines 1078–1165)

Vulnerability Details

1. deactivate_validator Fails to Route token_stake_amount to token_unbonding_amount, Permanently Stranding SPL Stake Collateral in stake_token_vault and Bypassing Unbonding Token Slashes (programs/paraloom/src/lib.rs:1634-1656)

Under the dual-stake validator architecture, register_validator (programs/paraloom/src/lib.rs:856-905) locks two collaterals for every active validator:

  1. Native SOL stake (validator_account.stake_amount >= validator_registry.minimum_stake) held in the ValidatorAccount PDA.
  2. SPL token stake (validator_account.token_stake_amount = credited_token_stake >= validator_registry.min_token_stake) held in the shared stake_token_vault PDA.

When a validator exits via unregister_validator or is deactivated by a slash in slash_validator (programs/paraloom/src/lib.rs:1113-1123), both collaterals are moved into their respective unbonding buckets (unbonding_amount and token_unbonding_amount):

let residual = validator_account.stake_amount;
validator_account.unbonding_amount =
    validator_account.unbonding_amount.saturating_add(residual);
validator_account.stake_amount = 0;
let token_residual = validator_account.token_stake_amount;
validator_account.token_unbonding_amount = validator_account
    .token_unbonding_amount
    .saturating_add(token_residual);
validator_account.token_stake_amount = 0;

However, in deactivate_validator (programs/paraloom/src/lib.rs:1634-1656), only the SOL half (v.stake_amount) is moved into v.unbonding_amount, while v.token_stake_amount is left untouched:

    pub fn deactivate_validator(ctx: Context<DeactivateValidator>) -> Result<()> {
        let was_active = ctx.accounts.validator_account.is_active;
        let stake = ctx.accounts.validator_account.stake_amount;
        let who = ctx.accounts.validator_account.validator;
        if was_active {
            let now_slot = Clock::get()?.slot;
            let v = &mut ctx.accounts.validator_account;
            v.is_active = false;
            v.unbonding_amount = v.unbonding_amount.saturating_add(stake);
            v.unbonding_slot = now_slot.saturating_add(UNBONDING_SLOTS);
            v.stake_amount = 0;
            let registry = &mut ctx.accounts.validator_registry;
            registry.total_active_stake = registry.total_active_stake.saturating_sub(stake);
            registry.active_validators = registry.active_validators.saturating_sub(1);
        }
        msg!("Validator deactivated: {}", who);
        Ok(())
    }

This creates two concrete on-chain failures:

  1. Permanent Irrecoverable Freezing of SPL Stake Tokens on withdraw_unbonded_stake (lines 1673-1746):

    • Because v.is_active is now false, the deactivated validator cannot call unregister_validator (which requires validator_account.is_active == true).
    • Once UNBONDING_SLOTS elapses, the validator's only exit path is withdraw_unbonded_stake.
    • withdraw_unbonded_stake reads let token_amount = validator_account.token_unbonding_amount; (line 1714), which is 0 because deactivate_validator never moved token_stake_amount into token_unbonding_amount.
    • At the end of withdraw_unbonded_stake, Anchor's #[account(mut, close = validator, ...)] constraint on WithdrawUnbondedStake::validator_account closes and zeroes the ValidatorAccount PDA.
    • Consequently, 100% of the validator's SPL stake tokens (>= min_token_stake, e.g. 10_000_000_000 token units) remain permanently locked inside stake_token_vault with the ValidatorAccount PDA deleted and no instruction capable of recovering them.

  2. Complete Bypass of Token Collateral Burning During the Unbonding Slash Window (slash_validator lines 1088-1093 & 1131-1138):

    • In slash_validator, when was_active == false (an unbonding validator), the at-risk token balance is read exclusively from validator_account.token_unbonding_amount (lines 1088-1093): 
      let old_token = if was_active {
    validator_account.token_stake_amount
} else {
    validator_account.token_unbonding_amount
};
let token_slash = (old_token as u128 * slash_percentage as u128 / 100) as u64;
    • For any validator deactivated via deactivate_validator, token_unbonding_amount is 0 (while token_stake_amount still holds the tokens), so old_token == 0 and token_slash == 0. Slashing that validator during its unbonding window burns 0 SPL tokens.

2. slash_validator Checks Only stake_amount < minimum_stake and Ignores token_stake_amount < min_token_stake When Enforcing Deactivation (programs/paraloom/src/lib.rs:1099-1104)

register_validator enforces both collateral floors (stake_amount >= validator_registry.minimum_stake at line 838 and credited_token_stake >= validator_registry.min_token_stake at line 885).

However, when an active validator is slashed in slash_validator (lines 1096-1104), the deactivation check only compares the SOL half against minimum_stake:

        if was_active {
            validator_account.stake_amount = old_stake.saturating_sub(slash_amount);
            validator_account.token_stake_amount = old_token.saturating_sub(token_slash);
            if validator_account.stake_amount < ctx.accounts.validator_registry.minimum_stake {
                validator_account.is_active = false;

If a validator registers with SOL above the floor (e.g., 1.5 * minimum_stake) and the exact minimum token stake (min_token_stake), a partial slash (e.g., 20%) reduces validator_account.token_stake_amount to 0.8 * min_token_stake (violating the registry's min_token_stake requirement) while validator_account.stake_amount remains >= minimum_stake. The validator stays is_active = true and continues settling transactions and voting in BFT quorums while holding less than the mandatory min_token_stake collateral.

             // toward the BFT quorum.
-            if validator_account.stake_amount < ctx.accounts.validator_registry.minimum_stake {
+            if validator_account.stake_amount < ctx.accounts.validator_registry.minimum_stake
+                || validator_account.token_stake_amount < ctx.accounts.validator_registry.min_token_stake
+            {
                 validator_account.is_active = false;
                 let registry = &mut ctx.accounts.validator_registry;
@@ -1645,8 +1647,12 @@ pub mod paraloom_bridge {
